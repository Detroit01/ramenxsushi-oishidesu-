0. JUDUL DOKUMENTASI

Perancangan Sistem Basis Data Point of Sale (POS) dan Manajemen Stok Bahan Baku pada Restoran Jepang “RamenXsushi-Oishidesu”

Dokumentasi lengkap perancangan basis data relasional mulai dari alur prosedur penjualan, pemetaan matriks relasi 10 entitas, tahapan normalisasi (Unnormalized hingga 3NF), diagram ERD dan LRS, sampai implementasi MySQL dan simulasi transaksi kasir, nomor meja, stok bahan baku dapur, serta laporan akhir bulanan.

01.

Cerita (Studi Kasus)

RamenXsushi-Oishidesu merupakan usaha yang bergerak di bidang kuliner dengan menyediakan berbagai makanan dan minuman khas Jepang, seperti sushi, ramen, donburi, appetizer, dessert, dan minuman. Dalam kegiatan operasionalnya, restoran melakukan pencatatan transaksi penjualan, pemesanan menu, pembayaran pelanggan, serta pemantauan stok bahan baku dapur setiap harinya.

Prosedur sistem penjualan pada RamenXsushi-Oishidesu adalah sebagai berikut:

Pelanggan datang ke restoran RamenXsushi-Oishidesu dan melakukan pemesanan makanan maupun minuman kepada bagian kasir. Pegawai kasir yang bertugas akan mencatat identitas kasir, data pelanggan, nomor meja pelanggan (M01–M10), serta daftar pesanan yang dipilih, kemudian pesanan diteruskan kepada bagian dapur untuk diproses. Bagian dapur menyiapkan makanan dan minuman sesuai pesanan yang telah diterima menggunakan stok bahan baku makanan yang tersedia di penyimpanan berdasarkan takaran resep masing-masing menu. Setelah pesanan selesai dibuat, makanan dan minuman diserahkan ke nomor meja pelanggan. Kasir kemudian melakukan perhitungan total harga berdasarkan menu yang dipesan, jumlah pesanan, serta harga masing-masing menu.

Pelanggan melakukan pembayaran sesuai total harga pesanan melalui metode pembayaran tunai, QRIS, maupun transfer. Setelah pembayaran diterima, kasir mencatat transaksi pembayaran dan memberikan bukti pembayaran (struk) kepada pelanggan yang memuat nama kasir, nomor meja, dan rincian menu. Data transaksi pesanan, pembayaran, serta pemakaian bahan baku selanjutnya disimpan sebagai arsip restoran dan direkap menjadi laporan akhir bulanan yang digunakan oleh pemilik maupun manajer untuk melihat rekap transaksi, total pendapatan bulanan, serta jumlah menu yang terjual.

04.

Normalisasi (Unnormal, 1NF, 2NF, 3NF)

A. Bentuk Tidak Normal (Unnormalized Form / UNF)

Tahap 1

Seluruh atribut dari struk kasir (termasuk nomor meja dan nama kasir), kartu stok bahan baku dapur, dan laporan akhir bulanan dikumpulkan mentah dalam satu tabel.

UNF_Oishidesu (id_pesanan, tanggal_pesanan, no_meja, status_pesanan, id_pegawai, nama_pegawai, jabatan, shift, id_pelanggan, nama_pelanggan, no_telepon, alamat, email, {id_menu, nama_menu, deskripsi_menu, id_kategori, nama_kategori, deskripsi_kategori, harga, stok_menu, jumlah, harga_satuan, subtotal, {id_resep, id_bahan, nama_bahan, satuan, stok_bahan, batas_minimum, supplier, takaran}}, total_harga, id_pembayaran, tanggal_pembayaran, metode_pembayaran, jumlah_bayar, status_pembayaran, id_laporan, periode_bulan, total_transaksi_bulanan, total_pendapatan_bulanan, menu_terlaris, tanggal_cetak)

B. Bentuk Normal Pertama (1NF)

Tahap 2

Menghilangkan seluruh repeating group sehingga setiap sel bernilai tunggal (atomik) dan menentukan kunci kandidat gabungan (id_pesanan, id_menu, id_bahan).

Oishidesu_1NF (id_pesanan, id_menu, id_bahan, tanggal_pesanan, no_meja, status_pesanan, id_pegawai, nama_pegawai, jabatan, shift, id_pelanggan, nama_pelanggan, no_telepon, alamat, email, nama_menu, deskripsi_menu, id_kategori, nama_kategori, deskripsi_kategori, harga, stok_menu, jumlah, harga_satuan, subtotal, total_harga, id_pembayaran, tanggal_pembayaran, metode_pembayaran, jumlah_bayar, status_pembayaran, nama_bahan, satuan, stok_bahan, batas_minimum, supplier, takaran)

C. Bentuk Normal Kedua (2NF)

Tahap 3

Memisahkan ketergantungan parsial (partial dependency) sehingga atribut transaksi utama masuk ke PESANAN_2NF (memuat no_meja dan data kasir), atribut produk ke MENU_2NF, inventori ke BAHAN_BAKU, serta tabel penghubung DETAIL_PESANAN dan RESEP_BAHAN.

D. Bentuk Normal Ketiga (3NF — Skema Final 10 Tabel)

Final 10 Tabel

Menghapus ketergantungan transitif (nama_pegawai, jabatan, shift dipisahkan ke tabel mandiri PEGAWAI; data pelanggan ke PELANGGAN; kategori ke KATEGORI; pembayaran ke PEMBAYARAN; serta arsip bulanan ke LAPORAN_BULANAN).

07.

Implementasi Database / MySQL

Sintaks DDL & DML lengkap untuk db_oishidesu mencakup 10 tabel (kategori, menu, pegawai, pelanggan, pesanan + no_meja, detail_pesanan, pembayaran, bahan_baku, resep_bahan, dan laporan_bulanan):

db_oishidesu_10_tabel.sql MySQL / MariaDB (10 Tabel) 
CREATE DATABASE IF NOT EXISTS db_oishidesu;
USE db_oishidesu;

-- 1. Tabel KATEGORI
CREATE TABLE kategori (
    id_kategori VARCHAR(10) PRIMARY KEY,
    nama_kategori VARCHAR(50) NOT NULL,
    deskripsi TEXT
);

-- 2. Tabel MENU
CREATE TABLE menu (
    id_menu VARCHAR(10) PRIMARY KEY,
    id_kategori VARCHAR(10) NOT NULL,
    nama_menu VARCHAR(100) NOT NULL,
    deskripsi TEXT,
    harga INT NOT NULL,
    stok INT NOT NULL DEFAULT 0,
    CONSTRAINT fk_menu_kategori FOREIGN KEY (id_kategori) REFERENCES kategori(id_kategori)
);

-- 3. Tabel PEGAWAI (Kasir, Koki, Manajer)
CREATE TABLE pegawai (
    id_pegawai VARCHAR(10) PRIMARY KEY,
    nama_pegawai VARCHAR(100) NOT NULL,
    jabatan ENUM('Kasir', 'Koki', 'Manajer') NOT NULL,
    shift ENUM('Pagi', 'Malam') NOT NULL,
    no_telepon VARCHAR(20)
);

-- 4. Tabel PELANGGAN
CREATE TABLE pelanggan (
    id_pelanggan VARCHAR(10) PRIMARY KEY,
    nama_pelanggan VARCHAR(100) NOT NULL,
    no_telepon VARCHAR(20),
    alamat TEXT,
    email VARCHAR(100)
);

-- 5. Tabel PESANAN (Dilengkapi id_pegawai Kasir & no_meja)
CREATE TABLE pesanan (
    id_pesanan VARCHAR(15) PRIMARY KEY,
    tanggal_pesanan DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    id_pelanggan VARCHAR(10) NOT NULL,
    id_pegawai VARCHAR(10) NOT NULL,
    no_meja VARCHAR(10) NOT NULL,
    total_harga INT NOT NULL DEFAULT 0,
    status_pesanan ENUM('Diproses Dapur', 'Disajikan', 'Selesai', 'Dibatalkan') NOT NULL,
    CONSTRAINT fk_pesanan_pelanggan FOREIGN KEY (id_pelanggan) REFERENCES pelanggan(id_pelanggan),
    CONSTRAINT fk_pesanan_pegawai FOREIGN KEY (id_pegawai) REFERENCES pegawai(id_pegawai)
);

-- 6. Tabel DETAIL_PESANAN
CREATE TABLE detail_pesanan (
    id_detail VARCHAR(15) PRIMARY KEY,
    id_pesanan VARCHAR(15) NOT NULL,
    id_menu VARCHAR(10) NOT NULL,
    jumlah INT NOT NULL,
    harga_satuan INT NOT NULL,
    subtotal INT NOT NULL,
    CONSTRAINT fk_detail_pesanan FOREIGN KEY (id_pesanan) REFERENCES pesanan(id_pesanan),
    CONSTRAINT fk_detail_menu FOREIGN KEY (id_menu) REFERENCES menu(id_menu)
);

-- 7. Tabel PEMBAYARAN
CREATE TABLE pembayaran (
    id_pembayaran VARCHAR(15) PRIMARY KEY,
    id_pesanan VARCHAR(15) NOT NULL UNIQUE,
    tanggal_pembayaran DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    metode_pembayaran ENUM('Tunai', 'QRIS', 'Transfer') NOT NULL,
    jumlah_bayar INT NOT NULL,
    status_pembayaran ENUM('Lunas', 'Menunggu', 'Gagal') NOT NULL,
    CONSTRAINT fk_pembayaran_pesanan FOREIGN KEY (id_pesanan) REFERENCES pesanan(id_pesanan)
);

-- 8. Tabel BAHAN_BAKU
CREATE TABLE bahan_baku (
    id_bahan VARCHAR(10) PRIMARY KEY,
    nama_bahan VARCHAR(100) NOT NULL,
    satuan VARCHAR(20) NOT NULL,
    stok_bahan DECIMAL(10,2) NOT NULL DEFAULT 0,
    batas_minimum DECIMAL(10,2) NOT NULL DEFAULT 0,
    supplier VARCHAR(100)
);

-- 9. Tabel RESEP_BAHAN
CREATE TABLE resep_bahan (
    id_resep VARCHAR(10) PRIMARY KEY,
    id_menu VARCHAR(10) NOT NULL,
    id_bahan VARCHAR(10) NOT NULL,
    takaran DECIMAL(10,2) NOT NULL,
    CONSTRAINT fk_resep_menu FOREIGN KEY (id_menu) REFERENCES menu(id_menu),
    CONSTRAINT fk_resep_bahan FOREIGN KEY (id_bahan) REFERENCES bahan_baku(id_bahan)
);

-- 10. Tabel LAPORAN_BULANAN (Arsip Rekap Akhir Bulan)
CREATE TABLE laporan_bulanan (
    id_laporan VARCHAR(15) PRIMARY KEY,
    periode_bulan VARCHAR(20) NOT NULL,
    id_pegawai VARCHAR(10) NOT NULL,
    total_transaksi INT NOT NULL,
    total_pendapatan INT NOT NULL,
    menu_terlaris VARCHAR(100),
    tanggal_cetak DATE NOT NULL,
    CONSTRAINT fk_laporan_pegawai FOREIGN KEY (id_pegawai) REFERENCES pegawai(id_pegawai)
);
