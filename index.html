0. JUDUL DOKUMENTASI

Perancangan Sistem Basis Data Point of Sale (POS) dan Manajemen Stok Bahan Baku pada Restoran Jepang “RamenXsushi-Oishidesu”

Dokumentasi lengkap perancangan basis data relasional mulai dari alur prosedur penjualan, pemetaan matriks relasi 8 entitas, tahapan normalisasi (Unnormalized hingga 3NF), diagram ERD dan LRS, sampai implementasi MySQL dan simulasi transaksi terintegrasi dengan stok bahan baku dapur.

Studi Kasus: F&B Japanese Casual Dining • Skema: 8 Tabel Terintegrasi • Fitur: POS Kasir & Inventori Bahan Baku
01.

Cerita (Studi Kasus)

RamenXsushi-Oishidesu merupakan usaha yang bergerak di bidang kuliner dengan menyediakan berbagai makanan dan minuman khas Jepang, seperti sushi, ramen, donburi, appetizer, dessert, dan minuman. Dalam kegiatan operasionalnya, restoran melakukan pencatatan transaksi penjualan, pemesanan menu, pembayaran pelanggan, serta pemantauan stok bahan baku dapur setiap harinya.

Prosedur sistem penjualan dan pengelolaan bahan pada RamenXsushi-Oishidesu adalah sebagai berikut:

Pelanggan datang ke restoran RamenXsushi-Oishidesu dan melakukan pemesanan makanan maupun minuman kepada bagian kasir. Kasir mencatat data pelanggan serta pesanan yang dipilih, kemudian pesanan diteruskan kepada bagian dapur untuk diproses. Bagian dapur menyiapkan makanan dan minuman sesuai pesanan yang telah diterima menggunakan stok bahan baku makanan yang tersedia di penyimpanan dapur (seperti mie ramen basah, beras Jepang, ikan salmon segar, kaldu paitan, nori, daging sapi slice, hingga bubuk matcha) berdasarkan takaran resep masing-masing menu. Setelah pesanan selesai dibuat, makanan dan minuman diserahkan kepada pelanggan. Kasir kemudian melakukan perhitungan total harga berdasarkan menu yang dipesan, jumlah pesanan, serta harga masing-masing menu.

Pelanggan melakukan pembayaran sesuai total harga pesanan melalui metode pembayaran tunai, QRIS, maupun transfer. Setelah pembayaran diterima, kasir mencatat transaksi pembayaran dan memberikan bukti pembayaran kepada pelanggan. Data transaksi pesanan, pembayaran, serta pemakaian stok bahan baku selanjutnya disimpan sebagai arsip restoran dan digunakan oleh pemilik untuk melihat laporan transaksi, total pendapatan, jumlah menu yang terjual, serta peringatan bahan baku dapur yang mulai menipis agar segera dilakukan pembelian ulang ke supplier.

04.

Normalisasi (Unnormal, 1NF, 2NF, 3NF)

A. Bentuk Tidak Normal (Unnormalized Form / UNF)

Tahap 1

Gabungan mentah seluruh atribut transaksi kasir dan data bahan baku dapur ke dalam satu tabel dengan repeating group.

UNF_Oishidesu (id_pesanan, tanggal_pesanan, status_pesanan, id_pelanggan, nama_pelanggan, no_telepon, alamat, email, {id_menu, nama_menu, deskripsi_menu, id_kategori, nama_kategori, deskripsi_kategori, harga, stok_menu, jumlah, harga_satuan, subtotal, {id_resep, id_bahan, nama_bahan, kategori_bahan, jumlah_stok, satuan, stok_minimum, harga_satuan_bahan, supplier, takaran_pakai, satuan_pakai}}, total_harga, id_pembayaran, tanggal_pembayaran, metode_pembayaran, jumlah_bayar, status_pembayaran)

B. Bentuk Normal Pertama (1NF)

Tahap 2

Menghilangkan seluruh grup berulang sehingga setiap kolom bernilai tunggal (atomik) dengan kunci kandidat gabungan (id_pesanan, id_menu, id_bahan).

Oishidesu_1NF (id_pesanan, id_menu, id_bahan, tanggal_pesanan, status_pesanan, id_pelanggan, nama_pelanggan, no_telepon, alamat, email, nama_menu, deskripsi_menu, id_kategori, nama_kategori, deskripsi_kategori, harga, stok_menu, jumlah, harga_satuan, subtotal, total_harga, id_pembayaran, tanggal_pembayaran, metode_pembayaran, jumlah_bayar, status_pembayaran, nama_bahan, kategori_bahan, jumlah_stok, satuan, stok_minimum, harga_satuan_bahan, supplier, takaran_pakai, satuan_pakai)

C. Bentuk Normal Kedua (2NF)

Tahap 3

Memisahkan ketergantungan parsial (partial dependency) sehingga atribut yang hanya bergantung pada sebagian kunci utama dipisah menjadi tabel mandiri (MENU_2NF, PESANAN_2NF, BAHAN_BAKU) dan tabel penghubung (DETAIL_PESANAN, RESEP_BAHAN).

D. Bentuk Normal Ketiga (3NF — Skema Final 8 Tabel)

Final 8 Tabel

Menghapus ketergantungan transitif (nama_kategori dipisah ke KATEGORI, data pelanggan ke PELANGGAN, dan bukti pembayaran ke PEMBAYARAN). Berikut adalah 8 tabel normal siap implementasi:

4. PESANAN
id_pesanan (PK), tanggal_pesanan, id_pelanggan (FK), total_harga, status_pesanan
5. DETAIL_PESANAN
id_detail (PK), id_pesanan (FK), id_menu (FK), jumlah, harga_satuan, subtotal
6. PEMBAYARAN
id_pembayaran (PK), id_pesanan (FK), tanggal_pembayaran, metode_pembayaran, jumlah_bayar, status_pembayaran
7. BAHAN_BAKU
id_bahan (PK), nama_bahan, kategori_bahan, jumlah_stok, satuan, stok_minimum, harga_satuan_bahan, supplier

07.

Implementasi Database / MySQL

Sintaks DDL & DML lengkap untuk db_oishidesu mencakup 8 tabel, 21 menu, 12 pelanggan, 12 transaksi pesanan, serta 16 stok bahan baku makanan:

db_oishidesu_lengkap.sql MySQL / MariaDB (8 Tabel) 
CREATE DATABASE IF NOT EXISTS db_oishidesu;
USE db_oishidesu;

-- 1. Tabel KATEGORI
CREATE TABLE KATEGORI (
    id_kategori VARCHAR(10) PRIMARY KEY,
    nama_kategori VARCHAR(50) NOT NULL,
    deskripsi TEXT
);

-- 2. Tabel MENU
CREATE TABLE MENU (
    id_menu VARCHAR(10) PRIMARY KEY,
    id_kategori VARCHAR(10) NOT NULL,
    nama_menu VARCHAR(100) NOT NULL,
    deskripsi TEXT,
    harga INT NOT NULL,
    stok INT NOT NULL DEFAULT 0,
    CONSTRAINT fk_menu_kategori FOREIGN KEY (id_kategori) REFERENCES KATEGORI(id_kategori)
        ON UPDATE CASCADE ON DELETE RESTRICT
);

-- 3. Tabel PELANGGAN
CREATE TABLE PELANGGAN (
    id_pelanggan VARCHAR(10) PRIMARY KEY,
    nama_pelanggan VARCHAR(80) NOT NULL,
    no_telepon VARCHAR(20),
    alamat TEXT,
    email VARCHAR(80)
);

-- 4. Tabel PESANAN
CREATE TABLE PESANAN (
    id_pesanan VARCHAR(15) PRIMARY KEY,
    tanggal_pesanan DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    id_pelanggan VARCHAR(10) NOT NULL,
    total_harga INT NOT NULL DEFAULT 0,
    status_pesanan ENUM('Diproses', 'Selesai', 'Dibatalkan') NOT NULL DEFAULT 'Diproses',
    CONSTRAINT fk_pesanan_pelanggan FOREIGN KEY (id_pelanggan) REFERENCES PELANGGAN(id_pelanggan)
        ON UPDATE CASCADE ON DELETE RESTRICT
);

-- 5. Tabel DETAIL_PESANAN
CREATE TABLE DETAIL_PESANAN (
    id_detail INT AUTO_INCREMENT PRIMARY KEY,
    id_pesanan VARCHAR(15) NOT NULL,
    id_menu VARCHAR(10) NOT NULL,
    jumlah INT NOT NULL,
    harga_satuan INT NOT NULL,
    subtotal INT NOT NULL,
    CONSTRAINT fk_detail_pesanan FOREIGN KEY (id_pesanan) REFERENCES PESANAN(id_pesanan)
        ON UPDATE CASCADE ON DELETE CASCADE,
    CONSTRAINT fk_detail_menu FOREIGN KEY (id_menu) REFERENCES MENU(id_menu)
        ON UPDATE CASCADE ON DELETE RESTRICT
);

-- 6. Tabel PEMBAYARAN
CREATE TABLE PEMBAYARAN (
    id_pembayaran VARCHAR(15) PRIMARY KEY,
    id_pesanan VARCHAR(15) NOT NULL UNIQUE,
    tanggal_pembayaran DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    metode_pembayaran ENUM('Tunai', 'QRIS', 'Transfer') NOT NULL,
    jumlah_bayar INT NOT NULL,
    status_pembayaran ENUM('Lunas', 'Menunggu', 'Gagal') NOT NULL DEFAULT 'Lunas',
    CONSTRAINT fk_pembayaran_pesanan FOREIGN KEY (id_pesanan) REFERENCES PESANAN(id_pesanan)
        ON UPDATE CASCADE ON DELETE CASCADE
);

-- 7. Tabel BAHAN_BAKU (Inventori Bahan Makanan Dapur)
CREATE TABLE BAHAN_BAKU (
    id_bahan VARCHAR(10) PRIMARY KEY,
    nama_bahan VARCHAR(80) NOT NULL,
    kategori_bahan VARCHAR(40) NOT NULL,
    jumlah_stok INT NOT NULL DEFAULT 0,
    satuan VARCHAR(15) NOT NULL,
    stok_minimum INT NOT NULL DEFAULT 0,
    harga_satuan_bahan INT NOT NULL,
    supplier VARCHAR(80)
);

-- 8. Tabel RESEP_BAHAN (Komposisi Bahan per Menu)
CREATE TABLE RESEP_BAHAN (
    id_resep VARCHAR(10) PRIMARY KEY,
    id_menu VARCHAR(10) NOT NULL,
    id_bahan VARCHAR(10) NOT NULL,
    takaran_pakai INT NOT NULL,
    satuan_pakai VARCHAR(15) NOT NULL,
    CONSTRAINT fk_resep_menu FOREIGN KEY (id_menu) REFERENCES MENU(id_menu)
        ON UPDATE CASCADE ON DELETE CASCADE,
    CONSTRAINT fk_resep_bahan FOREIGN KEY (id_bahan) REFERENCES BAHAN_BAKU(id_bahan)
        ON UPDATE CASCADE ON DELETE RESTRICT
);
